# R7-105 zone create greenhouse FK and auto zone name

## 목적

구역 생성 모달을 제품 출시용 입력 구조로 정리한다. 구역은 반드시 기존 온실 테이블의 온실과 외래키로 연동될 수 있어야 하므로, 온실명은 DB 등록 온실 리스트 기반 드롭박스로 표현한다.

## 헤더 부연설명

기존 내부 작업 흔적 문구 대신 제품 출시용 문구를 사용한다.

```text
온실별 재배·운영 공간을 등록하고 저장 전 기준을 확인합니다
```

## 기본 정보

필드 순서:

```text
온실명 select → 구역명 input(readonly auto) → 구역 용도 select
```

### 온실명

- `greenhouseId` select
- 현재 DB에 등록된 온실 리스트를 option으로 표현한다.
- 저장 시 온실 테이블 외래키로 연동하기 위한 값이다.

### 구역명

- `name` input
- 선택 온실에 등록된 기존 구역 번호의 다음 번호를 자동 제안한다.
- 이 값을 **다음 구역 번호** 기준으로 산출한다.
- 예: 대표온실의 온실 번호가 `1`이고 기존 구역이 `1-1구역`, `1-2구역`이면 새 값은 `1-3구역`이다.
- 온실 드롭박스 option에는 `data-next-zone-name`을 넣고, 선택 변경 시 `data-r7-settings-zone-auto-name` 입력값을 갱신한다.

### 구역 용도

기본 옵션:

```text
재배 구역
육묘 구역
사무 구역
```

운영자가 쓸 수 있게 추가 구체화 옵션도 제공한다.

```text
실험 구역
자재 보관 구역
격리·검역 구역
```

DB `green_smart_settings_zones.purpose`에는 내부 영문 코드가 아니라 운영자 표시명과 동일한 한국어 라벨을 저장한다. 이전 UI에서 들어온 `cultivation`, `nursery`, `office`, `experiment`, `storage`, `quarantine` 값은 저장 직전 각각 `재배 구역`, `육묘 구역`, `사무 구역`, `실험 구역`, `자재 보관 구역`, `격리·검역 구역`으로 정규화한다.

## 구역 구성

```text
면적 number input, 단위 m²
배드 수 number input, 단위 개
```

- 면적 숫자 입력 기준: `m2`, `step=0.1`
- 배드 수 숫자 입력 기준: `count`, `step=1`

## 메모

```text
생성 사유 textarea
```

## 제거

기존 `신규 구역`, 자유입력 `구역 용도=재배`, `120㎡` 텍스트 입력은 구역 생성 모달에서 제거한다.
